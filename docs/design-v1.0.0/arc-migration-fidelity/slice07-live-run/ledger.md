## What Worked

- **Capturing the before-manifest as a real sha256 fingerprint (not just a node count) made "byte-identical after the dry-run" a mechanically checkable claim** rather than an eyeballed one — `find nodes -name '*.md' | sort | xargs shasum -a 256 | shasum -a 256` before and after the dry-run produced the identical composite hash, which is strong, cheap evidence a plain "git status is clean" doesn't fully cover (it wouldn't catch a write-then-revert-to-identical-content, unlikely as that is here).
- **Adjudicating the dry-run's count against the plan's "≈47" estimate by direct corpus inspection, rather than accepting either the estimate or the tool's number on faith, resolved a real (if small) discrepancy before it could become a mid-run surprise.** The estimate assumed a faithful non-stub arc/slice node existed somewhere in the corpus; none does — the one non-stub slice the baseline note gestured at is the retired tombstone. Worth the five extra minutes of `awk`/`grep` before firing.
- **Checking `git diff` on the specific project and retired-node files individually (not just trusting the aggregate skip count) is what actually proves F-5's exclusion, not just implies it.** An aggregate "46 skipped" could in principle hide a wrongly-touched node inside a big number; a per-file zero-diff check cannot.
