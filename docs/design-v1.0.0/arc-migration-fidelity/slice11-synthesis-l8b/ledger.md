## What Worked

- **Reusing the index/graph layers' already-list-shaped edge handling.** `odm-index`'s adapter/build
  (`edges.supersedes.push(...)`, `for supersedes in &edges.supersedes`) and `odm-core::graph` needed only
  a `Some`→`for` mechanical change, because every *other* multi-target edge kind (`depends_on`,
  `verifies`, `consumes`, `affects`, `tears`) already used exactly this shape — `supersedes` was the one
  edge kind still singular, and bringing it in line was additive, not a new pattern.
- **Building `check_supersession`'s cycle detector as an explicit-stack DFS from the start**, rather than
  patching the old single-chain `loop` to "sort of" handle branching, avoided a real correctness trap: an
  ad hoc extension of the old code would very plausibly have under-counted or duplicate-reported cycles
  through a branching node. The 6 new fixtures (dangling-among-multiple, self-supersede-among-multiple,
  branching-cycle, 3-way fan-out) exist specifically because a 2-node fixture suite cannot distinguish a
  correct multi-target implementation from a subtly wrong one.
- **Defining the deterministic join concretely, in code, rather than leaving it abstract** turned a
  vague ODD phrase ("a deterministic join") into something a fixture could actually gate on — and
  confirmed via `deterministic_join_is_order_sensitive_and_normalizes_each_source` that "order" and
  "per-source normalize" are not just words but load-bearing, testable properties.
- **Confirming ODD-0017/0018's L-8b target state by citation evidence** (which closed arcs depend on
  them as settled authority) rather than guessing from the audit's general framing was slower but
  produced a disclosed, defensible answer instead of a silent assumption — consistent with the
  cc-prompt's explicit "confirm the target state per doc... don't guess."
