## What Worked

- **Generalizing the existing `reconcile_source` (selfhost.rs) with one boolean flag**, rather than
  writing a parallel implementation for the reconcile case, kept `repair()`'s exact, already-tested
  behavior provably unchanged (its 4 pre-existing unit tests pass byte-for-byte unmodified) while
  giving `reconcile()` the re-snapshot policy for free — one code path, two call-site policies, never
  silently conflated (F-5's own criterion, satisfied structurally rather than by convention).
- **`legacy::discover`/`self_host`'s `discover` already walk the *current* tree and match by identity
  (`number` / `(type, number)`), not a remembered path** — this meant moved-source re-discovery (F-2)
  fell out of the existing sourceless paths *for free*, and the only genuinely new code needed was the
  already-sourced case (`mapping::reconcile_source`, `selfhost::reconcile`). Recognizing this before
  writing code avoided building a second, redundant re-discovery mechanism.
- **Investigating the live corpus directly** (`odm node show`, raw node-file inspection under
  `.worktrees/odm/nodes`) **before designing the fixtures** confirmed the exact concrete shapes s13 will
  hit — #13 sourceless+moved, #17/#18 sourced+moved+drifted, #20 sourceless+not-moved+drifted — so every
  fixture in this slice models a real case, not a hypothetical one, without ever writing to the live
  store itself.
- **Reusing `mapping::Reconciled` from `selfhost.rs` via import** (rather than defining a second,
  differently-shaped type) followed the codebase's own established precedent (`Repaired` is defined once
  in `selfhost.rs` and imported into `mapping.rs`) — one shared report shape for both families' reconcile
  outcome, not two independently-evolving ones.
