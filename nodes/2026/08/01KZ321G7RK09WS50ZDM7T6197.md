# Slice 03 cc-prompt -- native authoring commands (programmatic surface)

**You are CC.** Real toolchain, with tests. Read, in order: **ODD-0026** (Accepted) sec. 2.5 (fork E
-- the authoring contract) and sec. 2.1/2.2; **ODD-0013 v2.6** sec. 2.3 (the **author-vs-odm field
boundary** just folded in); then this slice's `slice-doc.md` + `ledger.md` (F-1..F-10). The
acceptance anchor is **F-7** (SS-4: create AND update a node body via `./bin/odm`, no hand-edit).

## Ground truth (read before coding)

- `node new` today (`odm-cli/src/lib.rs` NodeCommand::New, `commands.rs::new`) takes only
  `type`/`name`/`parent` and mints `Origin::Planned` with a stub body. You are adding body/metadata
  paths and switching authored creations to `Origin::Authored` (slice 02's model -- reuse
  `Source::authored`, do not reinvent).
- There are **no** `Edit`/`Set`/`SetBody` node subcommands yet -- all new.
- `serde_json` and `toml` are **already** workspace deps -- use them for the dual-format partial. Do
  **not** add an `$EDITOR`/editor-spawn dependency; the interactive surface is out of scope (slice 07).
- Authored nodes are already valid in `check` (slice 02, `content_validity`); lean on that.

## The principle: odm owns the seam

Every surface you hand the author is single-grammar: pure-markdown **body** (no front-matter) or a
**structured metadata partial**. odm is the only code that fuses them into the on-disk `---`+body
node file. The author never edits the fused file through these commands.

## What to build

1. **The canonical metadata partial** -- one type of author-owned fields only (`name`/title, `type`,
   `edges.part_of`, status intent, `tags`; per ODD-0013 v2.6). Load from `--metadata=<file>`,
   dispatched on extension (`.json`/`.toml`), through one canonical form.
2. **Validate-before-write** -- before writing: validate the partial against the schema **and** the
   author-vs-odm boundary. Reject (clear error, write nothing) any partial that sets an odm-owned
   field: `id`, `number`, placement/`path`, or the `source`/provenance record. The body is prose --
   never parsed, never a rejection source.
3. **`node new <type> <name>`** -- add `--metadata=<file>`, `--content=<file.md>` (+ `--body=<str>`
   and `--from-file=<md>` as content aliases). Mint `origin: authored` + `Source::authored`, odm
   owning `id`/`number`/placement. Bare `node new` (no body) -> authored stub + returned ref.
   Keep `--dry-run`; add `--json`.
4. **`node set <ref> <field> <value>`** -- field-addressed metadata edit (author-owned only;
   re-validate; boundary-enforced). `--dry-run`/`--json`.
5. **`node set-body <ref> --from-file=<md>`/`--body=<str>`** -- replace the whole body as pure
   markdown; re-attach the unchanged frontmatter. `--dry-run`/`--json`.

## Constraints -- do not regress

- **The seam invariant:** `set-body` must leave the frontmatter **byte-identical** (only the body
  changes); `set` must leave the body byte-identical (only the named metadata field changes). Add
  fixtures asserting both.
- **Boundary is load-bearing** (F-2): an author partial can never set `id`/`number`/`path`/`source`.
  Test each rejection.
- **Authored, not planned:** a body-carrying `node new` mints `origin: authored` (not `Planned`);
  `check` stays green (reuse slice 02's model). A migrated/existing node is untouched by these verbs.
- **Names/titles carry no role metadata** (ODD-0013 sec. 2.1).

## Definition of done

F-1..F-10 reach a final status; the SS-4 round-trip (new from metadata+content -> set -> set-body ->
show, check green, no hand-edit) passes end-to-end; JSON and TOML partials are equivalent;
validate-before-write rejects odm-owned fields and invalid partials; `--dry-run`/`--json` on each
verb; `make check` green. Close with the per-row ledger walk + a bubble-up to the arc (did this
deliver SS-4; what should the arc-plan or slice 04/07 note; the silent-drop diff). Flag anything
ODD-0026 sec. 2.5 under-specified for the interactive surface (slice 07).
