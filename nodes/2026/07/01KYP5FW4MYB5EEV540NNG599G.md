## What Worked

- **The "clone the frontmatter, mutate only the delta" pattern (s04's finding) generalized cleanly a second time.** `self_host`'s coordinate→source transition (F-2) reuses the exact shape `repair` already used — clone, set the touched fields, `with_source(...)`, persist — rather than reconstructing a `Frontmatter` field by field. Two independent call sites now share the idiom; worth defaulting to it for any future in-place node update.
- **Unifying the stub-replace and non-stub-verify paths in `repair()` under one `verify_body_hash` call turned out to be the simplest correct design**, not a compromise: computing `new_body` first (source text for a stub, the existing body otherwise) and then always gating `new_body` against `source_body` meant F-4 (no-op backfill) and F-5 (surfaced drift) fell out of the *same* code path instead of needing a branch in the error handling — one fewer place for the two behaviors to drift apart.
- **Source-path matching subsumed the F-7 coverage gap almost for free.** Because every node `self_host`/`migrate` creates already carries `source` (since s03), adding the primary `source_paths.contains(...)` check to `doc_coverage` closed the named-arc gap without needing any new data — the fix was in the *matcher*, not the *model*.
- **Keying `named_arc_number` off a plain FNV-1a hash of the slug (no external crate) kept the change small** and made the "recomputable from the slug alone" property trivial to test directly (no fixture needed for the core property, just the two-argument pure function).
