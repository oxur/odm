## What Worked

- **Making `relativize` tolerant of *both* an absolute and an already-relative input (via `strip_prefix(...).unwrap_or(path)`) turned "detect the transition case" into "the same code path handles both cases automatically."** There is no `if legacy_absolute { ... } else { ... }` branch anywhere in the matching logic — a stored path's *form* simply never has to be inspected before computing its canonical key, which is exactly what let the re-mint guard (F-4) fall out of the existing `by_source` matching structure instead of needing new branching logic.
- **`Path::join`'s "an absolute second argument replaces the whole path" behavior meant `resolve_from_anchor` needed zero special-casing for the legacy-absolute read path** — the same one-line function correctly resolves both a canonical-relative stored entry and a not-yet-rewritten absolute one. Worth remembering as a general Rust `std::path` idiom: when a value might be "still in the old absolute form or already migrated to relative," `PathBuf::join` against a fixed anchor is often the simplest inverse, not a bespoke transition check.
- **Investigating the dry-run's one unexpected "create" by direct inspection (does a node already claim that number? does the plan directory genuinely postdate s07?) rather than either blindly stopping or blindly proceeding was the right instinct, and fast** — the same discipline the s07 dry-run-adjudicate step established. A hard gate's *purpose* (catch a broken transition guard) and its *literal wording* ("any create") aren't always the same thing when the world has legitimately moved between snapshot and dry-run; the fix is to check the purpose directly, not to relax the gate.
- **`coverage.rs` needing the same anchor treatment as `selfhost.rs`, despite not being named in the cc-prompt's file list, was caught early** by reading the ledger's own F-6 criterion literally (cross-root coverage stability) before writing any code — worth continuing to cross-check a cc-prompt's named seams against its own ledger criteria before assuming the file list is exhaustive.
